# 弹幕倍速与连续展示（2026-10-25）

## 根因与处理

检查项目实际使用的 `app/libs/danmaku.aar`：DanmakuView 没有旧代码反射调用的 `setSpeed(float)` 或 `setSpeedFactor(float)`。原来的 updateTimer 回调为空，媒体倍速没有推进弹幕时间轴。页面另将文字滚动时长除以播放倍速，改变了文字移动速度，但没有改变新弹幕出现的时刻。重复 READY/播放通知还会调用 start(position)，重启绘制。

现在由 DanmakuClock 持有媒体位置、倍速与单调时间锚点，逐帧提供弹幕时间，倍速改变时保留当前时间。渲染线程不调用播放器；主线程每 250ms 采样实际进度，在 250ms 内平滑校正误差，校正速度限制为当前播放速度的正负一半，避免回退。暂停、缓冲停止推进，显式 seek 直接定位。

PlaybackDanmakuView 使用库的外部计时模式，配合 Choreographer 帧节奏；禁止使用不受帧节奏约束的非阻塞独立更新线程。关闭库按墙钟计算的空闲等待，避免 3x/5x 下等待过长漏过弹幕。隐藏、暂停和释放仍停止绘制；仅弹幕正在显示和运行时采样播放器，暂停、隐藏、停止、重置和释放不保留采样循环。此选择会让已开启弹幕的稀疏区间也随帧更新，尚未测量低端实体设备的耗电或 CPU 影响。

控制器区分首次启动、暂停恢复和重复状态通知。重复通知不再 start 或 seek；普通暂停恢复不清空当前弹幕，隐藏后重新显示才定位到当前视频。TV/手机统一取消“滚动时长再除以倍速”，长按加速与松键不重设整套弹幕样式。保留用户设置的滚动速度、字号、透明度和行数。

## 回归与验证

- 12 项新增控制器测试：1→3→5→1 每帧连续、分数倍速、重复 READY、不跳变校正、实际媒体慢于理论 5x、暂停/缓冲、隐藏恢复、前后跳转、延迟准备、换集重置、停止释放及无效倍速。
- 恢复旧的空 updateTimer 时，首批 10 项测试失败；恢复时间推进后通过。慢媒体场景还复现了校正过慢导致的秒级领先，调整校正窗口后通过。
- 手机直播拖动的旧测试用 Unsafe 创建未初始化控制器，已改为正常构造并注入确定性时钟，保留原有行为断言。
- 临时只读 API34 Google APIs 模拟器，独立 codextest 包，本地 240 秒视频与 1200 条弹幕，使用 Activity 的真实 DanmakuContext。TV 经 dispatchKeyEvent 发送上键按下、长按及松键；手机经实际加速/恢复处理函数。均覆盖 1.25→3→5→1.25、暂停、暂停时跳至 60 秒和恢复。
- TV Exo、手机 Exo、TV IJK 原生场景全部通过。切速后保留已有弹幕索引，左坐标继续向前，渲染时间实际递增；不是仅检查播放器倍速字段。最后一轮阶段末采样最大媒体/弹幕时钟偏差约 316ms（TV Exo），IJK 约 208ms。不同负载下偏差可能更大，这不是帧率或硬件性能保证。
- TV 945、Mobile 918 项 Java 单测全部通过，两端 Java arm64 Debug 普通构建通过；两端 lint 无错误。普通 APK 包名恢复为 com.fongmi.android.tv，DEX 没有测试 Receiver。

原生测试使用新建的临时模拟器 emulator-5556，没有操作已有 Android_TV_1080p / emulator-5554。未验证实体遥控器、手机长按触摸、平板布局实际渲染、其他 ABI 和 Python flavor；未升级弹幕库或修改预置二进制。
