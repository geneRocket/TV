# M3u8AdFilter 审查与修复

基线：`99b4647ad`。检查媒体/主播放列表分支、广告区间与 URI 识别、过滤后的播放状态恢复、字幕白名单以及 Exo 数据源入口；不调整广告特征库或替换解析器。

## 已复现的问题

| 位置 | 触发条件与旧行为 | 根因与修复 |
|---|---|---|
| `isVodPlaylist` | EVENT 列表结束、追加 ENDLIST 后，原本保留的广告分片被删除；MEDIA-SEQUENCE 不变，后续分片的推导序号发生变化 | ENDLIST 被直接视作允许过滤的点播。显式 EVENT 现在始终优先保护；无 EVENT 的完整点播及显式 VOD 保持原过滤行为 |
| `hasExplicitAdResourceTag` | `EXTINF` 与正常 `.m4s` 分片之间的 MAP 使用 `ads/init.mp4`，会误删正常分片；相同 MAP 放在 EXTINF 之前却不删 | 把初始化资源名称直接当作后续媒体广告证据。MAP 继续作为必需播放状态保留，不再仅凭其名字判定媒体分片为广告 |
| `filterMinorHostSegments` | 正常随机文件名 `AD1veWOf.ts` / `aD5b9wgLiG.ts` 位于备用 CDN 时被删，同主 CDN 下却能保留 | 少数域名过滤绕过已有 AD+数字文件名碰撞保护。少数域名自身不再确认这种弱特征；明确广告路径/标签以及前置结构规则仍有效 |

每个问题均先添加针对性测试并确认失败，再修改实现。备用 CDN 测试同时断言明确广告被移除、全部正常媒体与顺序保留；MAP 测试同时检查初始化状态仍在对应片段前。

## 其余边界

- 直播、LL-HLS、字幕播放列表继续按已有保护规则处理；字幕白名单上限 512，增删查均同步。
- 隐式字节范围、按序号派生 IV 的加密流在删片会破坏完整性时回退；MAP/KEY/不连续边界与节目时间锚点恢复逻辑保留。
- 主播放列表继续保留最后可用路线和媒体组；相对地址识别使用最终重定向 URL，输出保留原 URI。
- Exo 数据源仍只对完整、从零开始的请求尝试过滤，读取上限 2 MiB；超限回放已读字节，普通运行时异常回退原内容。
