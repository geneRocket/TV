# App UI 检查（2026-10-28）

## 检查范围

覆盖共享、TV、手机 UI 的静态检查：173 份布局 XML（共享 5、TV 88、手机 80，含不同尺寸资源），现有两端 Lint 报告，以及首页/搜索/分类、历史/收藏、播放和直播页面、共享及平台弹窗的高风险入口与生命周期代码。Activity XML 中显式焦点跳转的目标均能在本布局或包含树中找到。重复 include ID 多数通过分层 ViewBinding 使用，没有批量改名。

## 已修复

| 模块 | 可复现问题 | 修复与验证 |
| --- | --- | --- |
| TV、手机字幕调节 | 248dp 固定窗口放不下 6 个按钮，原生层级中只剩 5 个，“搜索”被裁掉 | 6 个 48dp 等分按钮、适配可用窗口宽度；支持旋转，统一按主题着色并补充按钮说明。原生检查确认全部可见，TV 遥控器能到达搜索 |
| 手机选集 | 倒序 120 集、每页 40 集显示 `120 - 79`、`80 - 39`，范围与页面内容不符 | 改为 `120 - 81`、`80 - 41`、`40 - 1`；单测已确认原算法失败、修复后通过 |
| 手机选集重建 | 相同弹窗视图重建后再次追加页签，页签超过实际页数 | 重建前清空标题，保存集数与模式参数；Pager 使用弹窗自己的 Fragment 生命周期，销毁视图时解除 mediator 和 adapter。原生验证视图重建和 Activity 重建后都恰好 3 页 |
| 手机定时关闭 | 按系统返回关闭弹窗后，Timer 仍持有已关闭弹窗的回调 | 在视图销毁时按对象身份解除回调，避免旧弹窗清掉新回调；不停止实际倒计时。原生返回检查和 2 项回调测试通过 |
| 共享播放器选择 | 固定 320dp 宽，在更窄窗口没有适配，重建也需要重新连接 Activity listener | 按窗口可用宽度限制，并在配置变化时更新；重新连接当前 Activity。窄屏原生检查覆盖 240dp 的分享入口可见性 |
| TV 推送二维码 | 没有浏览器时点击二维码触发 `ActivityNotFoundException`，进入崩溃页 | 捕获缺少/不可用浏览器，保留二维码和地址并提示改用其他设备。隔离设备禁用浏览器后已复现原崩溃，修复后确认仍停留推送页 |

字幕调节弹窗重建时如果原字幕 View 已丢失，会关闭无效弹窗，避免继续操作过期播放器 View。

## 校验

- `:app:verifyRefactor` 通过，日志 `/tmp/tv-app-ui-final-verify.log`。包含两端 Java Debug、TV Python arm64 Debug 构建与运行时模块测试。
- 强制重跑 Java 单测：TV 965、手机 940，失败/错误/跳过均为 0。新增分页标签测试 2 项（两端），手机回调测试 2 项。
- Lint 0 错误，TV 170、手机 282 条警告；没有宣称全部警告均已清理。
- 普通 Java APK 的 Dex 不含测试 Receiver。测试只安装独立 `codextest` 包，未覆盖原应用。
- 原生设备：自建 API 34 模拟器，手机常规宽度 320dp；TV 页面在横屏运行。设备检查使用真实布局、返回键和 D-pad，受控选集数据为 120 集，不依赖外部播放接口。

## 限制

这是一轮全局静态检查与重点原生回归，不代表每个按钮、每个站点、每种数据和每台设备都已穷举。真实点播/直播视频中的完整覆盖层组合、投屏设备、外部播放器、扫码、权限拒绝流程、漫画/文件浏览的实际内容、大字体及所有分屏尺寸没有逐一设备验收。页面巡检中的历史/收藏为空数据；搜索页原生巡检预授予测试包麦克风权限，不能据此推断权限交互已通过。
